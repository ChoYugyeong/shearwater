# M1 분담과 리뷰 (2026-11-10 ~ 11)

참석: 클로드(구현·합치기), 코덱스 `review-agent`(실제 kubectl 확인), 딥시크 `review-agent`(watch·Table 테스트, 저장소 리뷰). 사용자가 한도 때문에 일부를 다른 에이전트에 넘겨 합치라고 지시했다.

| 누가 | 무엇 | 결과물 |
|---|---|---|

두 에이전트는 서버 코드를 고치지 않았고 커밋하지 않았다. 클로드가 결과물을 읽고 직접 돌린 뒤 커밋했다.

## 코덱스가 알려 준 것

- `hack/m1-check.sh` 103개 통과(kubectl v1.36.6으로 91개, kubectl.exe v1.36.0으로 12개). `hack/m0-check.sh`도 47개 그대로 통과. 클로드가 2026-11-11에 다시 돌려 같은 숫자를 확인했다.
- **`hostPath.type`이 우리 타입에 없다.** `type: DirectoryOrCreate`가 든 매니페스트는 `apply`(Strict)에서 400(`unknown field "...hostPath.type"`)이다. 흔히 쓰는 필드라서 M2에서 hostPath를 실제로 붙일 때 지원할지 정해야 한다. 재현: `hack/testdata/m1/hostpath-type.json`. → **미결(M2).**
- `kubectl edit`는 터미널이 없으면 PATCH를 보내기 전에 멈춘다(이 WSL 환경). 스크립트는 `script`로 가상 터미널을 준다. 서버 문제가 아니다.
- 저장만 필드 경고는 새로 넣거나 바뀐 값에만 나온다. 처음에는 같은 값에도 다시 나올 것으로 기대하고 테스트를 썼다가 고쳤다. → 정책으로 문서에 적는다(반영).
- `apply`가 전략 종류를 바꿀 때 `$retainKeys`와 함께 `rollingUpdate: null`도 보낸다. 볼륨 종류 교체도 `emptyDir: null`을 같이 보낸다(기록 31·32번).
- `delete`의 대기와 `wait`는 이름 fieldSelector의 watch-list(`sendInitialEvents=true`)를 쓴다(기록 38·39번). watch-list는 `rollout status`만의 것이 아니다.

## 딥시크가 알려 준 것

처음에는 딥시크의 Reason 답장 두 번이 프로토콜 오류로 전달되지 않아 사용자가 요약을 전달했다. 2026-11-11 마감 검수 중 딥시크가 작성한 전문 `2026-11-11-m1-review-deepseek.md`를 저장소에서 확인했다. 이 전문에는 M0 저장소 리뷰 답도 포함되어 있다.

- **버그: `Store.Changes`에 `limit=0`을 주면 panic.** 배치가 찼는지 보는 검사가 `changes[-1]`을 읽는다. 서버는 항상 200을 넘겨서 드러나지 않았다. → **반영(커밋 `a465467`).** 0 이하의 limit은 "무제한"도 "0건"도 아니고 호출한 쪽의 오류로 보고 error를 돌려준다. 테스트 추가.
- compact, `Changes`의 next 규칙, 허브, M0의 쓰기 경로, 유휴 쓰기 0, M2 첫 확인 순서를 봤고 watch·Table 경로에서 서버가 틀린 곳은 찾지 못했다고 한다. 전이표는 코드와 일치.
- 테스트 24개(전이표 × 셀렉터 7종 × 시퀀스, 실제 스트림 11가지, Table 10가지)가 통과한다.

## 클로드가 구현하면서 정한 것 (리뷰 대상)

- strategic merge patch 기대값과 Protobuf 기대 객체를 실제 apimachinery v0.36.6으로 뽑았다(`hack/oracle`, 별도 Go 모듈). `sw`와 그 테스트는 `k8s.io`를 가져오지 않는다. → **사용자 결정(2026-11-11): 레포에서 빼고 자료만 남긴다.** 프로그램은 git 기록(`483e994:hack/oracle`)에 있다.
- 쿠버네티스 라이브러리가 패닉하는 입력(`$setElementOrder`를 병합 키 없는 객체 목록에)과 모르는 `$` 지시어는 422로 거절한다.
- Protobuf 본문의 프로브·affinity·securityContext는 표를 만들지 않고 거절한다(매니페스트 안내). `kubectl create <종류>`와 `debug --copy-to`(baseline)는 이 필드를 보내지 않는다.
- `dnsPolicy: ClusterFirst`, `sessionAffinity: None`은 경고하지 않는다(kubectl이 스스로 넣는 기본값).

## M0 리뷰 복구와 마감 보완 의견 (2026-11-11, 코덱스)

- 코덱스 M0 리뷰 원문을 `2026-11-10-m0-review.md`로 복구했다. 원 대상은 `dd3e581`이다. 최초 Reason 답장 `1WY5KWXB3TMGC890CWGJ2CCXVC`는 queued까지만 확인됐으므로, 앞 세션의 미수신 기록과 모순되지 않는다. 딥시크 답을 복구한 것은 아니다.
- 현재 `3598a0b`의 관련 소스를 다시 읽었을 때 다음은 여전히 보완 대상이다. 이번 재확인은 정적 대조이며 새 실행 결과는 아니다.
  1. `internal/api/handlers.go:358`: spec만 비교해 generation을 올린다. Deployment의 annotation만 변경한 경우도 증가해야 한다는 M0 지적이 남아 있다.
  2. 같은 `replace` 경로와 `internal/apis/validate.go`: 삭제 중인 객체에 새 finalizer가 추가되는 것을 막는 이전/이후 metadata 비교가 없다.
  3. `internal/apis/decode.go:20`: JSON을 map으로 읽을 때 중복 키 정보가 소실되므로 Strict 중복 키 검출이 없다.
  4. `internal/api/handlers.go:146`: fieldValidation 값 검사가 unknown 필드가 있을 때만 실행된다. 정상 필드만 든 요청의 잘못된 enum도 거절해야 한다.
- 코덱스의 M1 마감 의견: 실제 kubectl 명령 경로 103개 통과는 확인했다. 위 네 경계 조건까지 해결됐다는 의미는 아니다. 각 항목의 최소 재현·회귀 검사를 별도 후속으로 고정하는 것을 권한다. 근거와 예상 동작은 복구한 M0 원문에 있다.
